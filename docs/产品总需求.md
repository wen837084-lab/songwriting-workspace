# PRODUCT MASTER PROMPT

我要开发一个长期使用的独立歌曲创作工作台：

# Songwriting Workspace

它服务于希望真正学习并独立完成歌曲创作的人，尤其适合：

- 完全没有歌曲创作经验的人
- 有一些想法，但不知道下一步做什么的人
- 已经开始写歌，但经常卡住的人
- 希望系统学习歌词、旋律、节奏、和声、结构和编曲的人
- 希望长期保存和发展很多首歌曲的人

这个产品最重要的目标不是：

“帮用户快速得到一首歌。”

而是：

“帮助用户逐渐获得自己完成歌曲创作的能力。”

---

# 一、最高产品原则

整个产品必须始终遵守：

> Guide the creator. Never become the creator.

中文理解：

> 指导创作者，但不要成为创作者。

系统可以：

- 帮用户整理想法
- 拆解创作过程
- 提出问题
- 保存用户自己的素材
- 帮用户规划下一步
- 解释创作知识
- 提供练习
- 帮用户识别自己卡在哪里
- 指导用户进行音乐实验
- 帮用户记录实验结果
- 帮用户进行自我检查
- 帮用户管理歌曲版本
- 帮用户长期学习 songwriting

系统不可以：

- 自动写歌词
- 自动续写歌词
- 自动给下一句
- 自动改写歌词
- 自动生成 Hook
- 自动生成标题
- 自动生成旋律
- 自动生成 MIDI melody
- 自动替用户选择旋律
- 自动生成完整和弦进行作为答案
- 根据情绪直接给用户“应该使用的和弦”
- 自动完成编曲
- 告诉用户应该加入哪件乐器
- 替用户选择哪个 Take 最好
- 判断一首歌好不好
- 给歌曲打分
- 给创作者评级
- 给不同版本排名
- 替用户做创作决定

所有真正属于歌曲的创作内容必须来自用户本人。

---

# 二、产品不是“一首歌工具”

这个产品是长期使用的 Workspace。

不是：

打开网站
→ 写一首歌
→ 完成
→ 网站失去作用

正确结构是：

Songwriting Workspace
├── Song Project A
├── Song Project B
├── Song Project C
├── Song Project D
└── ...

用户未来应该可以在这里管理几十首甚至上百首歌曲。

# 六、IDEA / EXPLORE

这一阶段不要让用户立刻写歌词。

核心原则：

Collect before creating.

首先问：

“你现在已经有什么？”

可选：

- 一个想法
- 一个故事
- 一句话
- 一个画面
- 一种情绪
- 一段旋律
- 一个节奏
- 一组和弦
- 一个声音
- 什么都没有

然后开始探索。

不要一次显示很多问题。

一次只问一个。

例如：

- 最近有什么东西一直在你脑子里？
- 有没有一个人？
- 有没有一件事情？
- 有没有一个画面？
- 有没有一个记忆？
- 有没有一个动作？
- 有没有一个声音？
- 有没有一个物件？
- 有没有一句一直记得的话？
- 有没有一个你说不清楚的感觉？
- 当时和现在有什么不同？

所有问题必须允许：

Answer
Skip
Back
Add note

所有输入进入：

Material Library

素材可以标记类型：

Scene
Emotion
Phrase
Memory
Sound
Person
Object
Event
Dialogue
Melody Idea
Rhythm Idea
Harmony Idea
Other

不要自动总结用户素材。

不要自动将素材变成歌词。

# 七、DEFINE

这一阶段的目标不是系统替用户决定主题。

而是：

让用户自己做选择。

可以问：

“这首歌其实是在讲什么？”

“你最想让别人听完以后感受到什么？”

“如果只能留下一个画面，你留下什么？”

“这件事情最矛盾的地方是什么？”

“事情发生时的你，和现在的你有什么不同？”

“从素材库中选出三个最舍不得删掉的东西。”

保存为：

Song Intent

例如：

coreIdea
desiredFeeling
coreImage
centralConflict
selectedMaterials

所有答案必须由用户本人填写。

# 九、REWRITE / REFLECTION

系统不直接修改用户歌词。

而是提供自我检查工具。

## Specific vs Abstract

逐行让用户自己标记：

Specific
Abstract
Unsure

不要自动判断。

---

## Repetition

系统可以机械统计词语出现次数。

例如：

“雨”出现 5 次。

但不能说：

“重复太多。”

让用户自己判断是否需要修改。

---

## Emotion Map

用户自己填写：

Chorus:
Verse 2:
Bridge:

对应的情绪。

帮助用户观察：

有没有变化？

但不要自动评价。

## Song Intent Check

然后问：

“现在的歌曲仍然围绕它吗？”

# 十五、LEARNING SUPPORT

这是整个产品非常重要的一层。

核心原则：

Create first.
Learn when needed.

不要强迫用户先上课再写歌。

不要把教程全部铺在创作页面。

在每个主要步骤提供一个不抢注意力的入口：

“我卡住了”

或：

“这一步需要什么能力？”

Learning Panel 默认关闭。

用户主动打开。

---

## Learning 分三层

### QUICK UNDERSTANDING

1–3 分钟。

回答：

- 这个概念是什么？
- 为什么有用？

### PRACTICE

5–10 分钟。

提供一个小练习。

练习的目标是训练能力。

不能直接替用户完成当前歌曲。

### DEEPER LEARNING

更完整的知识内容。

# 十八、AI COACH

核心创作流程必须不依赖 AI。

AI API 不可用时：

用户仍然可以完成整个创作流程。

AI 只作为：

Songwriting Coach
Learning Navigator
Process Guide

不是：

Songwriter
Composer
Arranger

AI 只能在用户主动请求时出现。

例如：

“I’m stuck.”

“Help me understand what I need to learn.”

“Explain this.”

“Help me diagnose the problem.”

---

## AI 可以做

1. 帮用户判断可能卡在哪个能力维度
2. 推荐 Learning Library 中相关 Skill
3. 解释创作概念
4. 提出反思问题
5. 给出练习
6. 帮用户描述自己卡在哪里
7. 帮用户找到下一步学习方向

---

## AI 严禁

- 写歌词
- 续歌词
- 改歌词
- 提供候选歌词
- 提供 Hook
- 生成标题
- 生成旋律
- 提供 melodic phrase
- 生成 MIDI melody
- 生成完整 chord progression
- 根据用户情绪直接给出创作答案
- 替用户做 Arrangement
- 替用户挑选 Take
- 说某个版本最好
- 评价作品质量

---

## AI System Prompt 必须包含

“Never provide creative material that could be directly inserted into the user's song.

Do not write lyrics, melodic ideas, song titles, hooks, chord progressions, arrangement choices, or creative alternatives.

Your role is to diagnose process problems, explain concepts, ask reflective questions, and suggest exercises.

Always return creative agency to the user.”

---

## AI 推荐结构化返回

bottleneckType

reasoningSummary

suggestedSkill

reflectionQuestions

exercise

returnToCreationPrompt

不要向用户显示模型内部 chain-of-thought。

# 二十一、GARAGEBAND PRACTICE GUIDE

可以在这些阶段出现：

Melody
Rhythm
Harmony
Arrangement
Demo

按钮：

“去 GarageBand 试一下”

这是 Guide。

不是 Integration。

每一次 Practice 包含：

## GOAL

这一轮只解决一个问题。

例如：

“比较三种 Chorus 旋律方向。”

---

## BEFORE YOU OPEN GARAGEBAND

显示当前歌曲信息：

Current Song
Current Section
Current BPM
Current lyrics
Current experiment question

---

## IN GARAGEBAND

只告诉用户如何建立测试环境。

例如：

打开一个工程。

设置当前 BPM。

打开 Metronome。

准备录制 Chorus。

不要提供创作答案。

---

## TRY

改变一个或几个变量。

例如 Melody：

Take A:
保持说话节奏，只改变音高。

Take B:
改变句尾。

Take C:
改变整体节奏。

注意：

不能提供实际旋律。

---

## LISTEN FOR

让用户自己观察：

- 哪一种符合 Song Intent？
- 哪一种让歌词更自然？
- 哪一种更值得继续探索？
- 有什么意外发现？

系统不做选择。

---

## RETURN TO WORKSPACE

清楚显示：

“完成实验后，回到工作台记录你的发现。”

# 三十二、最终边界检查

最后逐条验证：

1. 一个 Workspace 是否可以拥有很多 Song Projects？

2. 不同 Project 数据是否完全隔离？

3. 用户完成一首歌以后是否还能继续创建新的歌曲？

4. 如果 AI API 完全关闭，产品是否仍然完整可用？

5. 所有歌词是否来自用户本人？

6. 所有旋律是否来自用户本人？

7. 所有和弦决定是否由用户本人完成？

8. 所有编曲决定是否由用户本人完成？

9. AI 是否提供了任何可以直接放进歌曲的创作内容？

如果有，删除。

10. Learning 是否只在用户需要时出现？

11. Learning 是否帮助创作，而不是阻挡创作？

12. GarageBand 是否仍然只是网站外部的实验环境？

13. 网站是否没有尝试控制 GarageBand？

14. GarageBand Practice 是否清楚告诉用户：

为什么去？

要试什么？

听什么？

回来记录什么？

15. 网站是否避免重新发明 DAW？

16. 零基础用户是否知道下一步做什么？

17. 有经验用户是否可以跳过基础步骤？

18. 用户能否从不同创作入口开始？

19. 每个 Project 是否拥有自己的 Version History？

20. Skill Map 是否属于 Workspace？

21. GarageBand Experiments 是否绑定正确 projectId？

22. Melody Recordings 是否绑定正确 projectId？

23. 用户拥有 100 个 Projects 时，架构是否仍然合理？

24. 产品是否真的帮助用户“学习创作”，而不是“让软件替他创作”？

如果有任何答案是否定的：

先修架构。

不要通过新增更多功能来掩盖问题。
